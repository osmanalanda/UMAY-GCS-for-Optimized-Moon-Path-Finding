UMAY GCS: Autonomous Lunar Rover Navigation & Control System
UMAY GCS (Ground Control Station) is an advanced, real-time telemetry and navigation dashboard designed for autonomous lunar rovers. Developed by the Kün-Ay team, this system integrates high-level pathfinding algorithms with a robust communication layer to manage lunar exploration missions.

🚀 Overview
The application provides a comprehensive interface for monitoring rover telemetry, visualizing lunar terrain via an occupancy grid, and executing autonomous navigation using the A* (A-Star) algorithm. It is designed to interface seamlessly with Simulink/Simscape environments for hardware-in-the-loop (HIL) testing.

✨ Key Features
A Navigation Engine:* Implements a high-performance A* algorithm with 8-directional movement support and Euclidean heuristics.

Dynamic Occupancy Grid: A 50x50 grid-based map that handles static lunar features (craters, rocks) and updates dynamically with sensor data from Simulink.

Simulink/Simscape Integration: Real-time data acquisition via UDP/TCP protocols for synchronized simulation.

Live Telemetry Dashboard: Monitoring of critical flight data including velocity, heading, battery health, CPU temperature, and signal strength.

Mission Control Logs: A detailed navigation log that tracks A* route calculations, maneuver commands, and obstacle alerts.

Path Visualization: Real-time plotting of the rover's trail, active A* paths, and target waypoints.

🛠 Tech Stack
Language: Python 3.10+

GUI Framework: PySide6 (Qt for Python)

Communication: Socket Programming (UDP/TCP)

Algorithms: A* (Pathfinding), Occupancy Grid Mapping

Styling: Custom CSS-based Dark Mode "Space Palette"
🛰 Connection Settings
To interface with external simulations (like Simulink):

Navigate to the Connection Panel in the dashboard.

Select the protocol (UDP is recommended for real-time performance).

Set the Host IP (default 127.0.0.1) and Port (default 25000).

Ensure your Simulink model is sending data in JSON format.

🗺 Navigation Logic
The system uses a weighted cost map where:

Red Cells: Obstacles/Craters (Inaccessible).

Amber Cells: High-slope areas (High traversal cost).

Blue Dotted Line: The optimal path generated by the A* engine.

The rover automatically switches to "Recalculating" mode if a new dynamic obstacle is detected on the current path.
